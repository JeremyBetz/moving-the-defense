# Post–Phase 4 Data Strategy

## Purpose

Future datasets must answer prospectively stated scientific threats rather than be pooled for sample size. The statistical hierarchy is:

**frames ⊂ intervals ⊂ possessions/sequences ⊂ players ⊂ teams ⊂ matches**

Millions of frames are not millions of independent observations. Replication should primarily concern matches, teams, and providers—not tiny frame-level p-values.

## Frozen dataset roles

The intended inferential sequence is explicit: **Metrica Game 1 development → Metrica Game 2 held-out validation → prospectively specified IDSSE external replication → only then larger contextual or provider-robustness datasets.** Metrica Game 3 is not a substitute for the IDSSE step.

### Metrica Sample Game 1

**Role:** development and research history. It supported Phases 0–3 and supplied the frozen Phase 4 activity cuts. It must not be relabeled as held-out evidence.

### Metrica Sample Game 2

**Role:** first untouched held-out validation. **Status:** completed in Phase 4B. It supports narrow cross-match replication of focal-relative path within the Metrica sample environment.

### IDSSE / DFL data

**Intended role:** first serious external, multi-match replication of the focal-relative geometric primitive.

Prior repository research records seven complete Bundesliga/2. Bundesliga matches, official optical/TRACAB tracking at 25 Hz, and synchronized event/metadata. Its independent environment addresses the main next threat: was Game 1→2 replication only a same-provider, two-match property? Do not download or inspect focal-departure outcomes before a dedicated protocol is written and frozen.

### Metrica Sample Game 3

**Potential role:** same-provider implementation or portability sanity check only if prospectively justified. It is outside the primary inferential sequence, should not be inspected now, and must not replace the independent IDSSE replication simply because it is convenient.

### PFF / Gradient World Cup data

**Potential later role:** larger-scale contextual or expected-trajectory modeling and attacker-associated response. It should not be consumed merely as more replication data if IDSSE can answer external replication first. Broadcast-derived visibility, occlusion, and estimated positions are measurement limitations, not preprocessing inconveniences to hide.

### SkillCorner open data

**Potential later role:** cross-provider or broadcast-tracking robustness. Detected versus extrapolated positions must remain explicit measurement-quality strata or limitations.

### Alfheim / other data

**Potential later role:** sensing-technology robustness where it answers a specific scientific question. Different datasets should not be pooled indiscriminately.

## Likely next empirical phase—not executed

The likely next phase is **Phase 4C: external cross-match replication of focal departure using IDSSE**.

Candidate research question:

> Does the focal-relative path primitive exhibit stable measurement behavior across multiple professional matches from an independent tracking dataset?

A future protocol may consider computability and data quality; match-level distributions and variation; focal and collective activity relationships; common-translation invariance; contemporaneous versus misaligned references; window/smoothing robustness; player/team/match hierarchy; and provider/reference sensitivity. Detailed success thresholds are not frozen here. Provider differences must not be tuned away to reproduce Metrica's numerical distribution.

Phase 4C must be prospectively specified before IDSSE inspection. This document fixes dataset purpose, not an executable protocol.
